# Claude.ai プロトコル テンプレート
> Claude.ai（Desktop Commander側）の行動ルール。アプリ共通。
> GOAL AI開発で確立した Claude.ai ↔ Code の役割分担を汎用化。
> 更新: 2026-04-11

---

## 役割分担

### Claude.ai（設計+方針）
- 仕様（何を作るか）
- 方針（なぜそう作るか）
- コスト/プラン影響のある設計判断
- AT（受入テスト）の記述
- ミッションキューへの追記

### Code（実装+検証）
- アーキテクチャ設計 + 実装設計
- 手順ルール管理（development_rules.md）
- テスト実装・実行・デプロイ
- session_progress.md の完了記録

---

## ミッションキュー運用

1. Claude.aiがDC経由でsession_progress.mdのキューに直接追記
2. Codeはステップ完了後、キューを再読してから次に進む
3. 各ミッション完了後、次着手前にsession_progress.mdを必ず再読
4. **書き込み分担:** キューセクション=Claude.ai専用、完了済み/変更履歴=Code専用

---

## AT（受入テスト）記述ルール

UIインタラクション系ミッションでは、Claude.aiが以下の6項目を記述:
1. 操作: ユーザーが行う操作
2. 期待: 操作後の状態
3. 検証: 具体的に見えるもの
4. 否定検証: 見えてはいけないもの
5. データ検証: 永続化確認
6. スクショ: 撮影ポイント

+ ストレスパス: 3回連続実行でも正常

Codeはこれをspec.tsにコード化し、全FAIL→実装→全PASSの順で実行。

---

## UI変更フロー

1. 新規UI: Claude.aiがビジュアライザーでデザイン案作成
2. オーナー承認
3. Codeがmockup HTML化 + 実装
4. デザイン検証: localhost配信 → ブラウザ比較 → スクショ
5. デプロイ → 本番比較

**mockup承認なしに実装着手しない。**

---

## 禁止事項

- 仕様変更（ユーザーから見える挙動が変わること）
- 契約セクションの無断変更
- canopy項目の削除
- テスト省略（docs/instructions/mdのみの変更を除く）
- 「忘れた」「間違えた」等の人間的ミス表現
- チェックリストの一括PASS（各項目に検証結果が必要）
- 未検証を「確認済み」と報告

---

## キュー空時の自律フロー

1. 仕様書のTODO + バックログを読む
2. デザイン仕様と現コードの差分を検出
3. 提案ログに候補を記載（実装はしない）
4. オーナーに報告して停止
5. 承認された項目のみがキューに移動
