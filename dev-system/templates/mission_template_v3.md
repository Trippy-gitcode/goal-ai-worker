## AT（受入テスト）6項目ルール — G8準拠

UIインタラクション系ミッションでは、以下の6項目をATに必ず含める:

1. **操作**: ユーザーが行う具体的な操作手順
2. **期待**: 操作後に達成される状態
3. **検証**: 具体的に何が画面に見えるか
4. **否定検証**: 見えてはいけないもの（前画面要素、エラー等）
5. **データ検証**: 永続化確認（リロード後も残存するか）
6. **スクショ**: 撮影タイミングと対象

+ **ストレスパス**: 同一操作の3回連続実行

## RED/GREENサイクル（G8）

各ミッション実行手順:
1. **spec.tsにATをコード化** → 実行 → 全FAIL確認（RED）
2. **実装** → spec再実行 → 全PASS確認（GREEN）
3. **L1スモーク** → bump-version → build → canopy → **L2回帰テスト** → deploy → health → tag → push

RED確認なしに実装着手することを禁止。

## GOAL AIからの教訓

- **unmount/cleanup保証**: 画面遷移でPreactのmount/unmountを必ず走らせる。状態漏れ(BUG-05)の構造的防止
- **cmd2は具体的に**: 「全件PASS」ではなく `grep -c ... | awk` で数値閾値
- **テスト影響欄は必須**: 変更範囲が影響するE2Eセクションを明記。書かないと回帰テスト漏れ
- **ストレスパスの重要性**: 1回は通るが3回目で壊れるバグは多い（状態リセット漏れ）
- **チェックリスト一括PASS禁止**: 各項目にタイムスタンプ+スクショが必要
