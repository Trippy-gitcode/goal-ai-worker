# AIレビューフロー改善案 — ペルソナ構成レビュー依頼

## 背景
ソロ開発者（PO兼任）がClaude Code（実装AI）+ Claude.ai（アドバイザーAI）で開発する体制。
AIレビュー基盤で仕様書・デザイン・コードの品質を担保している。
Phase Aデザインレビューで15ラウンド/132本のAPIコールを消費し、CRITICALが収束しない問題が発生した。

## 改善案: 2段階レビュー + diffレビュー + ゴールデンレビュー + 動的主審選定

### フロー（全レビュー種別共通）
```
初回: 全ペルソナ × 2モデル（GPT-5 + Gemini）= フルスキャン
  ↓ CRITICAL出た場合
修正ラウンド: 動的主審（初回で有効指摘が多かった上位2-3名）× 2モデル = diffのみ
  ↓ CRITICAL 0
ゴールデンレビュー: 全ペルソナ × 2モデル = フルスキャン（最大2回）
  ↓ CRITICAL 0
✅ 確定
```

### 動的主審選定ルール
- 初回フルスキャンの結果から、CRITICAL/HIGHを多く出し かつ false positiveが少ないペルソナ上位2-3名をCodeが自動選定
- 修正ラウンドではこの主審のみがdiffレビューを実施
- ゴールデンレビューでは全員に戻る

### 信頼度スコアリング
- Phase完了時にレビュー実績を集計
- 修正採用率 > 70% → A / 50〜70% → B+ / < 50% → B
- false positive率 > 30% → 1ランクダウン
- 信頼度Bのペルソナが出したCRITICAL → HIGH扱い（ADV判断で棄却可）

## レビュー依頼

上記の改善案について以下を評価してください:

1. **フローの有効性**: 2段階+diff+ゴールデンの構造は、収束問題（15ラウンド/CRITICAL単調増加）を解決するか？漏れやリスクはないか？
2. **動的主審選定**: 初回結果から自動選定するアプローチの妥当性。選定基準（CRITICAL/HIGH数 × false positive率）は適切か？
3. **ペルソナ構成の最適化**:
   - 各種別（A/B/C）のペルソナは過不足ないか？
   - 役割が重複しているペルソナはないか？
   - 欠けている視点はないか？
   - ソロ開発者の体制（リソース制約）を考慮して、削減すべきペルソナはあるか？
4. **信頼度スコアリング**: 採用率/false positive率による自動調整は実用的か？改善案は？
5. **全体のコスト効率**: Phase Aの132本→改善後の推定コスト削減率は現実的か？

CRITICALは「このまま導入すると品質低下やコスト増大を招く重大な問題」のみ。
