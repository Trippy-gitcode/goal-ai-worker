### 1.3 遷移アニメーション定義

| 遷移種別 | アニメーション | duration | easing |
|---------|-------------|----------|--------|
| ボトムタブ切替 | クロスフェード（opacity 0→1） | 200ms | ease-out |
| サブタブ切替 | 横スライド（左右方向に応じて） | 250ms | ease-out |
| ハーフモーダル表示 | 下から上昇 + backdrop fade | 300ms | cubic-bezier(0.32, 0.72, 0, 1) |
| ハーフモーダル閉じ | 下降 + backdrop fade out | 250ms | ease-in |
| フルスクリーン遷移（前進） | 右からスライドイン | 300ms | cubic-bezier(0.32, 0.72, 0, 1) |
| フルスクリーン遷移（戻り） | 左へスライドアウト | 250ms | ease-in |
| ドロワー | 左からスライドイン + backdrop fade | 300ms | ease-out |

### 1.4 戻りナビゲーション

| 画面 | 戻り方法 | 戻り先 |
|------|---------|--------|
| ハーフモーダル | backdrop タップ / 下スワイプ / ✕ボタン | 親画面 |
| フルスクリーン詳細 | 左上「←」ボタン / 左端から右スワイプ（iOS標準） | 前画面 |
| ドロワー | backdrop タップ / 左スワイプ（開いた方向に押し戻す） | 親画面 |
| 設定階層 | 左上「←」ボタン / 左端から右スワイプ（iOS標準） | 前設定画面 |
| ブラウザバック | モーダル表示中: 閉じる。フルスクリーン: 前画面。タブ間: なし（下記参照） | history.pushState管理 |

**history.pushStateポリシー:**
- **ボトムタブ切替:** pushStateしない。タブ切替を履歴に積むとAndroid戻るボタンでタブ間を延々と遡るアンチパターンになるため。タブはreplaceStateで現在の状態を更新
- **フルスクリーン遷移（S-14, S-35, S-37等）:** pushStateする。戻るボタンで前画面に戻る
- **ハーフモーダル/ドロワー表示:** pushStateする。戻るボタンでモーダル/ドロワーを閉じる。Androidの物理戻るボタン対応必須
- **未保存データがある状態のpopstate:** 確認ダイアログ表示（§2.3 S-13タスク編集のルールに準拠）。popstateイベントで `history.pushState` を再挿入してナビゲーションをキャンセル、確認後に `history.back()` を実行

### 2.2 ヒーロー領域の挙動

**通常状態（スクロール位置 = top）:**
- アバター: 80x80px
- レベル + 称号: 16px
- EXPバー: 幅100%、高さ8px

**スクロール中（下方向）:**
- トリガー: scrollY > 60px
- アバター: 80→32px に縮小（CSS transform: scale）
- レベル/EXP: 1行に横並び圧縮（「Lv.12 █████ 1,240/2,000」）
- ヒーロー領域高さ: 120px → 48px
- transition: 200ms ease-out

**キーボード表示時:**
- visualViewport.height 変化を検知
- ヒーロー領域を display:none
- スクロール領域を画面全体に拡張

### 2.3 Today セクション操作

**タスク行の構成:**
```
[完了⭕] [時刻] [タスク名] [所要時間] [ゴール色ドット]
```

**タスクタップ → 詳細パネル（S-11）:**
1. タスク行をタップ
2. ハーフモーダルが下から上昇（画面高さ60%）
3. パネル内容:
   - タスク名（大文字。編集不可）
   - ステータス（未完了 / 完了）
   - 開始時刻 / 所要時間
   - メモ（あれば表示）
   - ゴール紐付け（あれば表示。タップでS-14へ）
   - ボタン行: [編集] [削除] [進め方を聞く] [詰まりを相談]
4. 「進め方を聞く」「詰まりを相談」→ S-20 TALKに遷移。タスク名をコンテキストとしてAIに自動送信:
   - 進め方: 「「{タスク名}」の進め方を教えてください」
   - 詰まり: 「「{タスク名}」で詰まっています。助けてください」

**タスク完了（⭕タップ）:**
1. ⭕をタップ → 即座にチェックマーク表示（楽観的UI更新）
2. Undoスナックバー表示（画面下部、ボトムタブの上）
   - 「タスクを完了しました [取り消す]」（残り秒数カウントダウン表示付き）
   - 30秒後に自動消去（project_v1.md §3.2準拠。30秒間の取り消しを保証）
   - 30秒経過で自動消去 → 完了確定。以後の取り消し不可
   - **Undoスナックバーはトースト（§6.2）とは別コンポーネント。** トーストの3秒ルール・スタック制限は適用しない。画面下部にボトムタブの上16pxで固定表示。高さ48px。**UI表示は5秒で自動消去。Undo機能の有効期間は30秒。** スナックバー消去後もタスク行の⭕再タップで取り消し可能（design_system.md §8.12a と統一。ADV調停済み 2026-04-12）
   - **タブ切替時の挙動:** Undoスナックバーは全タブに跨って表示を維持する（タブ切替でも消えない）。30秒のカウントダウンは継続。どのタブからでも [取り消す] をタップ可能
   - **連続タスク完了:** 別タスクを完了した場合、前のUndoスナックバーは即時確定し、新しいスナックバーに置換される（スタックしない）。**設計決定:** project_v1.md §3.2の「30秒以内に取り消し」は直近1件のタスクに対してのみ保証する。複数スナックバーの同時表示は画面を圧迫し、操作混乱を招くため不採用。30秒経過後の完了取消は不可（project_v1.md §7.4「EXPは加算のみ（減算なし）」準拠。一度確定したEXPは巻き戻せない設計）
   - **Undo時のEXPバー巻き戻し:** [取り消す] タップ → チェックマーク解除アニメーション（scale 1→0、200ms）→ EXPバーが逆方向に縮小（新値→旧値、500ms）→ EXPフロートテキストは非表示。レベルダウンが発生する場合（Undoでレベルアップ前のEXP値に戻る場合）: レベル数字がカウントダウン + 称号テキスト変更（演出なし。静的に即時変更）
   - **TALK画面でのUndoスナックバー位置:** TALK画面では入力バーの上に表示する（ボトムタブの上ではなく入力バーの上。入力バーが表示されている場合のみ位置調整）。キーボード表示中は入力バーと共にスナックバーも上昇する
   - 「取り消す」タップ → チェック解除 + EXP返却
3. サーバーにPOST（/api/task/complete）
4. 成功 → EXP演出（§8参照）
5. 失敗 → チェック解除 + エラートースト「完了に失敗しました。再試行してください」

1. 「+タスクを追加」タップ
2. ハーフモーダル上昇

     - ゴール作成から7日以上経過している場合: 即時ゴール達成 → ゴール達成演出 + ボーナスEXP + Undoスナックバー30秒表示

3. 紐づく全タスクが完了した場合 → 7日ルール判定（§2.4 7日ルール参照）。7日経過済みなら自動でゴール達成演出（§8.3）。未経過なら完了待ち状態に遷移
4. **ゴール達成後のUndo:** ゴール達成演出が発火した後、最後のタスクをUndoした場合:

### 3.2 メッセージ送信フロー

1. 入力欄にテキスト入力（1文字以上で➤送信ボタンがアクティブに。0文字はグレーアウト）
2. ➤タップ or Enterキー → 送信
3. ユーザーバブルが即時表示（右寄せ）
4. AI側に「...」タイピングインジケータ表示（3ドットアニメーション）
5. ストリーミング開始 → 「...」がAIバブルに置換 → テキストが逐次追記
6. ストリーミング完了 → バブル確定 + タイムスタンプ表示
7. 自動スクロール: 新メッセージ/ストリーミング中は最下部に追従。ユーザーが上方スクロール中（過去メッセージ閲覧中）は追従しない → 画面下部に「↓ 新しいメッセージ」フローティングボタン表示

**入力バーの挙動:**
- 📎: 画像添付。タップ → OSのファイルピッカー。選択後に入力バー上にサムネイルプレビュー表示。✕で取り消し。初回画像添付時のみプライバシー注意: 「画像はAI分析のために外部サーバーに送信されます。個人情報が含まれる画像にご注意ください」ダイアログ表示（[了解] + 「今後表示しない」チェックボックス）
- 入力テキストは改行可能。デスクトップ: Shift+Enter。モバイル: キーボードの改行キー（Enter/Return）で改行、送信は送信ボタンタップのみ。入力欄は最大4行まで自動伸長。それ以上はスクロール
- キーボード表示時: flexboxでメッセージ領域が縮小（position:fixed不使用。iOS PWA対策）

### 3.3 タスク提案カード（会話→タスク化）

AIバブルの直後にカード形式で表示。チャットフロー内のインライン要素。

**単一タスク提案:**
```
┌─────────────────────────┐
│ 📋 タスクにしますか？      │
│ タスク名: 企画書を提出する  │
│ 期限: 4/18（金）           │
│ [登録する] [編集して登録] [✕]│
└─────────────────────────┘
```
- カード背景: テーマのsurface色 + 左ボーダー（アクセント色）
- [登録する] → 即時登録 → カードが「✅ 登録しました」に置換（0.5秒後にフェードで縮小）
- [編集して登録] → S-12タスク追加ハーフモーダルを表示（AIが提案したタスク名・期限を事前入力済み）。カード内インライン展開は画面スペースの制約上不採用（7項目のフィールドがチャット内に展開されるとスクロール・操作が困難になるため）
- [✕] → カード非表示（アニメーション: 高さ0に縮小、200ms）

**複数タスク提案:**
```
┌─────────────────────────┐
│ 📋 3つのタスクが見つかりました│
│ ☑ ジムに行く（明日 朝）     │
│ ☑ 歯医者（明日 午後）      │

└─────────────────────────┘
```
- 各行のチェックボックスで選択/解除
- [まとめて登録] → チェック済みのみ一括登録 → カード置換
- [個別に編集] → S-12タスク追加ハーフモーダルを表示（1件目のタスクが事前入力済み。保存後に次のタスクのモーダルが順次表示される。スキップ可）。単一タスクの場合の [編集して登録] と同じモーダル方式で統一

### 3.4 冒険EXP演出（TALK画面内）

AIが冒険EXPを検出した場合、AIバブルの後に演出:
1. AIバブル末尾に ✨ マーク点滅（0.5秒）
2. バブル下に冒険EXPカード表示:
```
┌─────────────────────────┐
│ ⚔️ 冒険を検出！            │
│ 「初めてプレゼンに挑戦した」 │
│ +50 EXP                   │
└─────────────────────────┘
```
3. カード出現アニメーション: scale(0.8→1) + opacity(0→1)、300ms
4. GROW画面のヒーロー領域のEXPバーにも非同期で反映（次回GROW表示時）
5. **冒険EXP 1日上限（2回）到達時:** 3回目以降の冒険検出では冒険EXPカードを表示するが、EXP数値を「+0 EXP（本日の上限に到達）」に変更。カードのアクセント色をグレー系に変更して視覚的に区別

**TALK画面でレベルアップ条件を満たした場合:**
- TALK画面にはヒーロー領域がないため、EXPバー伸長・アバター変化の演出は行わない
- 代わりにTALK画面内でレベルアップバナーのみ表示:「🎉 Level Up! Lv.{N} — {称号}」（画面上部。3秒表示。冒険EXPカードの下に表示）
- 紙吹雪パーティクルはTALK画面でも実行（§8.7パーティクル共通仕様に準拠）
- フルのレベルアップ演出（EXPバー光る + アバター変化）は次回GROW画面表示時に自動再生。フラグで1回限り再生を保証
- **ME画面のヒーロー領域:** TALKでEXP/レベルが変化した場合、ME画面に切替えた時にヒーロー領域のEXP/レベル/称号/アバターを最新値で描画する（演出なし。静的更新のみ）。フルの演出はGROW画面のみで再生

- **ヒアリングスレッド:** ヒアリングセッション中のスレッドには「🎯ヒアリング」ラベルを付与。中断再開可能

## 6. 共通UIパターン

### 6.1 ハーフモーダル
- 画面下部から上昇。高さ: コンテンツに応じて40-80%
- backdrop: rgba(0,0,0,0.4)。タップで閉じる
- 上部にドラッグハンドル（幅40px、高さ4px、角丸。中央配置）
- 下スワイプ（ドラッグハンドルからの50px以上）で閉じる。**スクロールとの競合回避:** モーダル内コンテンツがスクロール先頭にある場合のみ下スワイプでモーダル閉じが有効。コンテンツを下にスクロール中（scrollTop > 0）はスワイプによるモーダル閉じを無効化し、スクロール操作を優先する。ドラッグハンドル上からのスワイプは常にモーダル閉じとして機能する
- 閉じる時のアニメーション: 下降 + backdrop fade out（250ms）
- **未保存データ保護:** テキスト入力済みの状態で下スワイプ/backdrop タップ/✕ボタンによる閉じ操作が発生した場合 → 確認ダイアログ「入力内容が破棄されます。よろしいですか？」→ [破棄する] / [戻る]。入力が空の場合は確認なしで閉じる
- **iOS PWAキーボード対策:** テキスト入力フィールドにフォーカス時、モーダルがキーボードで隠れないようvisualViewport APIでモーダル位置を動的に調整する。position:fixedは使用しない（iOS PWAで不安定）。flexboxベースでモーダル内コンテンツをスクロール可能にし、入力フィールドが常に可視領域に収まることを保証。キーボード表示中はモーダルの高さを`window.visualViewport.height`に制約する

### 6.2 トースト
- 画面下部（ボトムタブの上、16px margin）
- 最大幅: 画面幅 - 32px
- 背景: テーマのsurface色 + shadow
- テキスト + 任意のアクションボタン（右端）
- 自動消去: 3秒（アクション付きの場合5秒）
- 出現: 下からスライドイン（200ms）
- 消去: 下へスライドアウト（200ms）
- 複数同時: 新しいトーストが古いトーストを押し上げる（スタック最大2件）

### 6.3 確認ダイアログ
- 画面中央モーダル。backdrop付き
- 構成: タイトル + 説明文 + [キャンセル][実行] ボタン
- 破壊的操作（削除/退会）: 実行ボタンは赤色
- backdrop タップ = キャンセル

### 6.4 スケルトンスクリーン
- データ読み込み中に表示。実際のレイアウトと同じ形状のプレースホルダー
- 色: テーマの background-secondary
- アニメーション: shimmer（左→右のグラデーション移動。1.5秒周期）
- 適用箇所: GROW（タスク/ゴールリスト）、TALK（メッセージ読み込み）、ME（プロフィール/友達リスト）、ゴール詳細

### 6.5 Pull-to-refresh
- GROW画面 / FRIENDS画面で有効
- 下に引く（60px以上）→ 円形スピナー表示 → データ再取得 → スピナー消去
- 適用外: TALK画面（上スクロールは履歴読み込みに使用するため）

### 6.6 インラインエラー
- フォーム入力のバリデーションエラー
- フィールド直下に赤テキスト（12px）。フィールド枠も赤に変化
- 例: タスク名が空 → 「タスク名を入力してください」

### 6.7 バッジ
- ボトムタブアイコンの右上に赤丸 + 白数字
- 適用: MEタブ（未読メッセージ/承認待ちリクエスト数）
- 数字が99超過 → 「99+」表示

| チップ | 選択/解除 | 色fill変化（150ms） |
| ボタン | アクション実行 | opacity 0.7→1（100ms。押下中は0.7） |

### 7.2 ロングプレス

| 対象 | トリガー | アクション |
|------|---------|----------|
| タスク行 | 500ms | ドラッグモード開始（並び替え） |
| 強み/弱みチップ | 500ms | 削除確認ダイアログ |
| メッセージバブル | 500ms | コピーメニュー表示 |

### 7.3 スワイプ

| 方向 | 対象 | アクション |
|------|------|----------|
| — | TALK画面左端 | **スワイプ無効**（iOS edge swipeと競合するため。ドロワーは☰ボタンタップのみで展開） |
| 左→右 | フルスクリーン詳細の左端 | 前画面に戻る（iOS標準のedge swipe）※PWA実装注記参照 |
| 左→右 / 右→左 | MEサブタブコンテンツ領域 | サブタブ切替 |
| 上→下 | ハーフモーダルのドラッグハンドル | モーダル閉じ |
| 上→下 | GROW/FRIENDS画面先頭 | Pull-to-refresh |
| ロングプレス | チャット履歴の会話行 | 削除ボタン表示（左スワイプ不使用。ドロワー閉じとの競合回避） |

**PWA実装注記（edge swipe）:**
iOS PWAではブラウザのネイティブスワイプバック（ページ履歴ナビゲーション）とSPAのカスタム遷移アニメーションが競合する可能性がある。対策:
- `overscroll-behavior-x: none` をルート要素に設定し、ブラウザのネイティブスワイプバックを抑制
- アプリ側でtouchイベントを監視し、左端20pxからの右スワイプをカスタムジェスチャーとして処理
- history.pushState()でSPA内遷移を管理し、popstateイベントでカスタム戻りアニメーションを実行
- スタンドアロンモード（display: standalone）ではブラウザUIが非表示のため、ネイティブスワイプバックは発生しない。ただし `navigator.standalone` のフォールバック確認を含めること

### 7.4 ドラッグ&ドロップ

| 対象 | 操作 | 結果 |
|------|------|------|
| Today内のタスク行 | ロングプレス→上下ドラッグ | タスクの表示順を変更（開始時刻による自動ソートを手動で上書き。手動順は保存される） |

- ドラッグ中: 対象行が半透明になり、影(elevation)が付く
- 他の行はスペースを開けてドロップ位置を示す
- ドロップ → 位置確定 → サーバーに順序保存

## 8. アニメーション仕様

### 8.1 タスク完了演出
1. ⭕タップ → チェックマーク出現（scale 0→1、200ms、ease-out）
2. タスク行全体が一瞬光る（background-colorがアクセント色に0.3秒→元に戻る）
3. EXPフロートテキスト「+10 EXP」が⭕の上方に浮上（translateY -40px、800ms、ease-out）→ opacity 0にフェードアウト
4. ヒーロー領域のEXPバーがアニメーション伸長（現在値→新値、500ms、ease-in-out）

### 8.2 レベルアップ演出
タスク完了のEXPバー伸長がバー末端に到達した時にトリガー:
1. EXPバー全体が光る（glow effect、300ms）
2. レベル数字がカウントアップ（旧Lv→新Lv、数字が回転するような遷移、400ms）
3. 称号テキストが変更（fade out→fade in、300ms）
4. アバターに変化がある場合（Phase変更時）:
   - アバターがglow→旧PNGがcross-fade→新PNGがscale(1.2→1)で出現（計1.5秒。PNGキャッシュ使用。project_v1.md §7.3準拠: SVG直接レンダリングはプロフィール詳細画面のみ）
   - 紙吹雪パーティクル（画面上部から降下、2秒間）
5. 全体を囲むバナー: 「🎉 Level Up! Lv.{N} — {称号}」（画面上部、3秒表示）

### 8.3 ゴール達成演出
紐づく全タスクが完了 or 手動完了（ゴール作成から7日以上経過時。7日未満の場合は§2.4の「完了待ち」参照）。
**1日1回制限:** ゴール達成ボーナス（+50 EXP）は1日1回まで（project_v1.md §4.2準拠）。同日2つ目以降のゴール達成時は演出を実行するが、バナーは「🎉 ゴール達成！」（EXP表記なし）に変更。EXPフロートテキストも非表示。ユーザーに混乱を与えないよう、演出の紙吹雪は維持しつつEXP関連の数値表示のみ省略する:
1. ゴール進捗バーが100%に到達するアニメーション（500ms）
2. 画面全体に紙吹雪パーティクル（2秒間。色はテーマのアクセントカラーバリエーション）
3. 中央バナー:「🎉 ゴール達成！ +50 EXP」（3秒表示。fade in→3秒維持→fade out）
4. ヒーロー領域のEXPバー伸長

### 8.4 冒険EXP検出演出
- TALKでの演出は§3.4参照
- 追加: 画面上部から金色のパーティクルが2-3個降下（1秒間）

### 8.5 ログインボーナス演出
- GROW画面初回表示時（1日1回）
- ヒーロー領域のEXPバー下に一時表示:「☀️ ログインボーナス +5 EXP」（fade in→2秒維持→fade out）

### 8.6 演出キュー（同時発火時の優先順位）

複数の演出が同時にトリガーされた場合（例: タスク完了→ゴール達成→レベルアップが同タップで発生）、以下の順序で**直列実行**する。並列実行しない。

| 優先順位 | 演出 | 待機条件 |
|---------|------|---------|
| 1 | タスク完了（§8.1） | — |
| 2 | ゴール達成（§8.3） | タスク完了のEXPフロートテキストがフェードアウト後 |
| 3 | レベルアップ（§8.2） | ゴール達成バナーの表示開始後（バナー表示中にレベルアップ演出を重ねてよい） |

**EXPバー伸長の一貫性:** タスクEXP（+10）→ゴールEXP（+50）の順にEXPバーがアニメーションする。レベルアップがゴールEXPで発火する場合、ゴールのEXPバー伸長がバー末端に到達した時点でレベルアップ演出が開始される。

**合計演出時間上限:** 全演出を合計して最大8秒以内。これを超える場合はゴール達成バナーの維持時間を短縮（3秒→1.5秒）。

### 8.7 パーティクル共通仕様
- 実装: Canvas 2D（パフォーマンス優先。CSS animationではない）
- パーティクル数: 紙吹雪=30-50個、金色=2-3個
- duration後にCanvasをremove（メモリリーク防止）
- Reduced Motionメディアクエリ対応: `prefers-reduced-motion: reduce` 時はパーティクルを省略し、テキストバナーのみ表示

## 9. エラー・異常系UX

### 9.1 ネットワーク断

**検出:** `navigator.onLine` + fetch失敗のハンドリング

**GROW画面:**
- 画面上部に固定バナー「オフラインです」（黄色背景。復帰時に自動消去）
- タスク一覧はService Workerキャッシュから表示
- タスク完了は可能（ローカル記録 → オンライン復帰時にサーバー同期）
- **オフライン時のEXP演出:** EXP付与演出は表示しない（project_v1.md §7.3準拠: サーバー権威モデル）。代わりにタスク完了チェックマークの横に「🔄 同期待ち」バッジを表示。EXPバーは変化させない。オンライン復帰後にサーバーがEXP計算→結果を反映→通常のEXP演出を再生。巻き戻しは発生しない設計
- タスク追加/編集は可能（ローカル記録 → 同期）
- ゴール操作も同様
- **Undoのオフライン挙動:** Undoスナックバーは通常どおり表示。取り消し操作もローカルに記録。サーバー同期時はUndoの最終状態のみ送信（完了取消済みなら完了イベント自体を送信しない）

**TALK画面:**
- 入力フィールドを無効化（グレーアウト）
- バナー「オフラインです。接続を復旧してください」
- 送信済み未応答メッセージ: 「送信中...」表示維持。復帰時に再送信

**ME画面:**
- キャッシュデータで表示。編集はローカル保存 → 復帰時同期
- **QRコード表示（FRIENDS）:** オフライン時はQRコード表示ボタンを無効化（グレーアウト + 「QRコードの表示にはインターネット接続が必要です」ツールチップ）。QRにはサーバー発行の一時トークンが必要なため、オフラインでは生成不可
- **QRスキャン:** オフライン時はQRスキャンボタンも無効化（トークン検証にネットワーク必須のため。スキャンしても相手のプロフィールを取得できず、友達リクエストを正しく構築できない）

**復帰時:**
- バナー消去
- バックグラウンドで全ローカル変更をサーバーに同期（冪等性保証。project_v1.md §7.3準拠）
- サーバーがEXP計算 → レベルアップ判定 → 結果をクライアントに通知 → EXP演出（フロートテキスト + バー伸長）をまとめて再生。レベルアップがあれば§8.2演出も続けて再生
- 同期完了 → トースト「同期完了」

## 10. アクセシビリティ

### 10.1 タップターゲット
- 最小サイズ: 44x44px（Apple HIG準拠）
- ボトムタブのタップ領域: タブ全幅 × 高さ56px
- チェックボックス⭕: タップ領域を48x48pxに拡張（視覚的な円は24x24px）
- 隣接するタップターゲット間の最小間隔: 8px

### 10.2 コントラスト比
- テキスト（通常）: 最低 4.5:1（WCAG AA）
- テキスト（大文字/見出し）: 最低 3:1
- アイコン/非テキスト要素: 最低 3:1
- 全4テーマで検証必須（design_system.mdで各テーマのコントラスト比を定義）

### 10.3 フォーカス管理
- モーダル表示時: フォーカスをモーダル内にトラップ（Tabキーでモーダル外に出ない）
- モーダル閉じ時: フォーカスをトリガー要素に戻す
- 画面遷移時: フォーカスを新画面の最初のインタラクティブ要素に移動
- 入力フォーム: Tab/Shift+Tabで順にフォーカス移動

### 10.4 スクリーンリーダー対応
- 全インタラクティブ要素に aria-label
- ステータス変化（タスク完了、EXP獲得等）は aria-live="polite" で通知
- 画像/アバターに alt テキスト
- プログレスバー: role="progressbar" + aria-valuenow + aria-valuemax
- ボトムタブ: role="tablist" + role="tab" + aria-selected
- モーダル: role="dialog" + aria-modal="true"

### 10.5 アニメーション配慮
- `prefers-reduced-motion: reduce` 時:
  - パーティクル省略
  - 遷移アニメーションを instant に短縮
  - shimmerアニメーション停止（静的なプレースホルダー色に）
  - EXPバー伸長は維持（情報伝達に必要）

- ログアウト: タップ → 未同期データの有無を確認。
  - **未同期データあり + オンライン:** 確認ダイアログ「同期されていないデータがあります」→ [同期してログアウト]（同期実行→完了後にログアウト） / [キャンセル]
  - **未同期データあり + オフライン:** 確認ダイアログ「同期されていないデータがあります。インターネットに接続してから再度お試しください」→ [そのまま強制ログアウト（データ消失）] / [キャンセル]。[強制ログアウト] は赤テキスト
  - **未同期データなし:** 確認ダイアログ「ログアウトしますか？」→ [ログアウト]
  - ログアウト実行 → セッション破棄 + ローカルデータ消去（CacheStorage, IndexedDB, localStorage, sessionStorage全削除。共有端末でのプライバシー保護） → S-00 ランディングページ
- メール変更（S-42）: タップ → 右スライド遷移。現在のメールアドレス表示 + 新メールアドレス入力 + 現パスワード入力 → [変更する] → 新メールアドレスに認証リンク送信 + 旧メールアドレスに「メールアドレスの変更がリクエストされました。心当たりがない場合はパスワードを変更してください」セキュリティ通知を送信 → 新メール認証完了で変更確定 → トースト「メールアドレスを変更しました」
- パスワード変更（S-43）: タップ → 右スライド遷移。現パスワード入力 + 新パスワード入力（8文字以上）+ 新パスワード確認入力 → [変更する] → サーバー側で他の全デバイスのリフレッシュトークンを失効（セキュリティ: アカウント乗っ取り対策）→ トースト「パスワードを変更しました。他のデバイスはログアウトされます」

## 14. アプリ起動フロー

### 14.1 リピーターユーザー（ログイン済み）

```
PWA起動 / ブラウザアクセス
  → Service Worker キャッシュチェック
  → スプラッシュ表示（ロゴ + アプリ名。最大2秒）
  → Supabase Auth セッション検証
     ├─ 有効 → S-10 GROW画面
     │   ├─ ログインボーナス判定（本日未付与なら +5 EXP 演出）
     │   └─ 未読通知バッジ更新
     └─ 期限切れ → リフレッシュトークンで再認証
         ├─ 成功 → S-10 GROW画面
         ├─ 失敗（オンライン） → S-02 ログイン画面
         └─ 失敗（オフライン） → ローカルキャッシュでGROW画面表示（読み取り専用ではない。タスク完了/追加はローカル記録可能。EXP演出は非表示で「同期待ち」バッジ表示。TALK画面は無効化。オンライン復帰時に再認証→同期）
```

### 14.2 新規ユーザー

```
ブラウザアクセス
  → S-00 ランディングページ
  → [サインアップ] → S-01（利用規約+プライバシーポリシー同意チェック必須）
  → メール入力 + パスワード設定
  → S-04 メール認証待ち画面（「メールを確認してください」+ 再送信ボタン）
  → メール内リンクタップ → 認証完了 → S-03 オンボーディング
  → 5ステップ完了 → S-10 GROW画面
```

### 14.3 退会取り消し（クーリングオフ期間中）

```
ログイン画面でメール/パスワード入力
  → account_status = deleted_pending 検出
  → 「アカウント削除が予約されています。削除をキャンセルしますか？」ダイアログ
     ├─ [キャンセルする] → account_status を通常に戻す

     │   └─ Freeだった場合: 通常のGROW画面
     └─ [そのまま削除] → ログアウト → S-00
```

| # | 項目 | 対応方針 |
|---|------|---------|
| B1 | 戻るボタン | **iOS PWA最重要課題。** ハードウェアバック/ブラウザバックともになし。全フルスクリーン遷移画面（S-14,S-35,S-37〜S-41）に左上「←」ボタン必須。ハーフモーダルは下スワイプ/backdrop/✕で閉じ可能。history.pushStateで遷移履歴を管理し、popstateイベントでモーダル閉じ/前画面に戻る |

| B3 | セーフエリア | CSS `env(safe-area-inset-top/bottom/left/right)` を全画面のpadding/marginに適用。ボトムタブ: `padding-bottom: calc(8px + env(safe-area-inset-bottom))`。ヒーロー領域: `padding-top: calc(8px + env(safe-area-inset-top))` |

### 16.5 ストレージ・オフライン（D項目）

| # | 項目 | 対応方針 |
|---|------|---------|
| D1 | Cache容量 | iOS≒50MB制限。キャッシュ戦略: アプリシェル（HTML/CSS/JS）= Cache-first。APIレスポンス = Network-first。画像 = Stale-while-revalidate。50MB以内に収まるようアセットサイズを監視（ビルド時にwarning） |
| D2 | Storage永続性 | iOS Safari 7日ITP: script-writable storage（localStorage/IndexedDB）が7日未使用で消去。iOS PWA standalone: 免除されるが報告不安定。**対策:** 重要データ（認証トークン/未同期タスク）はService Worker Cache APIにも二重保存。ユーザーにPWAインストールを強く推奨 |
| D3 | Safari↔PWA非共有 | Safariでログイン→PWAでは未ログイン状態。**対策:** PWAインストール誘導モーダルで「ホーム画面から開き直してください」と案内。ログイン画面にも注記 |
| D4 | Background Sync | iOS=非対応。**フォールバック:** オンライン復帰検知（navigator.onLine + fetch成功）時にSync関数を実行。§9.1のオフライン同期フローと統合 |
| D5 | 容量見積もり | navigator.storage.estimate()で残容量監視。残10%以下→古いチャット履歴キャッシュを自動削除。persist()リクエストで永続化を試行（iOS=無視される） |
