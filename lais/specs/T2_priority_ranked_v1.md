## 1. 評価軸 4 軸 + Tier 定義

### 1.1 評価軸 (4 軸、各 0-5 点満点)

| 軸 | 重み | 判定基準 (5 点満点) |
|---|---|---|
| **PO 重要度** | 30% | 5 = PO 11 件判断と完全整合 + #11 アップセル重点中軸寄与 / 4 = PO 整合 / 3 = 部分整合 / 2 = 無関係だが妨げない / 1 = PO 整合性低 / 0 = PO 整合性なし |
| **実装コスト** | 25% | 5 = 8h 以下 / 4 = 8-24h / 3 = 24-72h / 2 = 72-160h / 1 = 160-400h / 0 = 400h+ (低コスト = 高得点) |
| **リスク** | 25% | 5 = リスクほぼなし / 4 = 低リスク (回避策あり) / 3 = 中リスク / 2 = 高リスク (mitigation 必須) / 1 = 致命リスク / 0 = 法務破滅級 (低リスク = 高得点) |
| **効果** | 20% | 5 = LTV/CAC 大幅改善 + D30 50% 達成核心 / 4 = 競合差別化中核 / 3 = 体感品質向上 / 2 = 部分改善 / 1 = 微改善 / 0 = 効果不明 |

### 1.2 合計スコア計算式

```
合計スコア = (PO重要度 × 0.30) + (実装コスト × 0.25) + (リスク × 0.25) + (効果 × 0.20)
範囲: 0.0 〜 5.0
```

### 1.4 Tier 別判定基準

- **Tier P0 (即実装必須)**: 法務 / 倫理リスク mitigation 必須、Critical Bug、PO #1/#11 直結、コスト破綻防止、bus factor 復元

- **Tier P2 (次月実装)**: 友人 β 期前必須だが Week 5-12 で OK、Pro Custom defensibility、High 重大度
- **Tier P3 (将来検討)**: Medium / Low 重大度、撤回検討対象、一般公開期 (Week 13+) 着手 or 不着手

### 1.5 Tier 評価運用ルール

- 各エントリは **Tier P0 / Tier P1 / Tier P2 / Tier P3** のいずれか 1 つに分類
- 重複 ID (T1 + T1ADD + T2A/B/C で同一テーマを扱う場合) は最高優先度の Tier に集約
- PO 11 件判断 lock により、T1 重大度は本 Tier 評価で再算定 (Critical → Tier P3 降格 10 件、Low → Tier P1 昇格 1 件 = T1-A-051 retention)
- Stage 7「一気に適応」では **Tier P0 → Tier P1 → Tier P2** の順で着手、**Tier P3** は一般公開期 (Week 13+) 後 or 撤回
