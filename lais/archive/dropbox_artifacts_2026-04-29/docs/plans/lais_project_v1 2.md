## 1. プロダクト概要

### 1.1 コンセプト
**「自分の人生を主人公として生きるためのAIパートナー」**

ユーザーは自分の人生の主人公。Laisはその冒険を支えるパートナーとして、日々のタスク管理・目標達成・自己理解・成長の可視化をAIと共に行うアプリ。

### 1.2 ブランドメッセージ
「今日から、あなたはあなたの世界の主人公になる。洗練して生きよう。憧れの姿になるように。」

### 1.3 デザイン思想
ポケモンの**構造**（育成・図鑑・冒険・進化）を借り、見た目は**洗練**。
ゲーム画面は一切出さない。ゲームの「気持ちよさ」を持った洗練されたアプリ。

| ポケモンから借りる構造 | Laisでの表現 |
|---------------------|------------|
| 進化（コダック→ゴルダック） | ユーザーアバターがレベルアップで変化（洗練されたビジュアル） |
| 図鑑 | 自分の特性・強みを「発見」してコレクション＋出会った人を記録 |
| バッジ・ジムリーダー | マイルストーン達成の演出 |
| フィールド画面 | タイムラインを「今日の冒険」として表現 |
| バトル演出 | タスク完了時の爽快なアニメーション |

### 1.4 ターゲットユーザー
**一次ターゲット:** 自己成長に興味がある20-30代
**二次ターゲット:** 目標はあるが行動に移せない人

**ペルソナ:**
- 25歳、社会人3年目。副業やスキルアップに興味あるが、仕事後の時間をSNSで浪費
- 28歳、転職を考えている。自分の強みが分からず、何から始めればいいか迷っている
- 32歳、運動習慣を作りたいが3日坊主を繰り返している

### 1.5 競合ポジショニング
| アプリ | 強み | ユーザーが不満を感じるポイント（実際のレビューから） |
|-------|------|-------------------------------------------|
| Habitica | 最も深いゲーミフィケーション。RPG要素でモチベーション維持 | UIが煩雑。HP損失が不安を生む。タスク未完了がパーティに被害→ストレス。ギルド廃止でコミュニティ崩壊。アップデート後のクラッシュ頻発 |
| Finch | 罰なしの自己慈愛モデル。バーチャルペットが癒し。Free版が充実 | 本格的なタスク管理ができない。12時間待機メカニクスが煩わしい。有料版が装飾のみで割高（$39.99/年）。Android版の品質が低い |
| Habitify | クロスプラットフォーム同期。美しいUI | Free版が3習慣のみ→「無料を騙っている」と不満。ウィジェット更新不具合。30-45秒フリーズの報告多数 |
| Streaks | ミニマリストで美しい。Apple Health連携 | iOS限定。24習慣の上限 |
| Loop | 完全無料・広告なし。シンプル | Android限定。機能がベーシックすぎる |

**Laisの差別化ポイント:**
1. **AIパートナーによる対話型コーチング** — 他アプリにないAI対話が核心機能
2. **罰なし＋構造化された目標管理** — Finchの優しさ＋Habiticaの深さを両立
3. **EXP＝本当の人生経験** — タスク消化ゲームではなく「挑戦」に重みを置く
4. **ソーシャル図鑑** — 出会いを記録し、互いの成長を可視化する新しいソーシャル
5. **アバター経済** — 装飾購入による自己表現＋収益モデル

## 2. ビジネスモデル

### 2.1 プラン構成（4段階 + アイテム課金）

| プラン | 月額（税込） | AI対話 | AIモデル | その他 |
|--------|-----------|--------|---------|-------|
| Free | ¥0 | 20回/日 | GPT-4o mini相当 | 育成/図鑑/EXP全機能開放 |
| Basic | ¥580 | 100回/日 | GPT-5 + Gemini Flash | — |
| Pro | ¥1,580 | 300回/日 | GPT-5 + Claude Sonnet + Gemini Pro | 冒険EXP検出精度向上 |
| Premier | ¥4,980 | 無制限（フェアユース上限1,000回/日） | GPT-5 + Claude Opus + Gemini Pro | 月3枚アイテムチケット+優先サポート |

**設計原則:**
- Freeでも「主人公体験」の核心（育成の実感、成長の可視化、ソーシャル）を全開放
- 制限するのはAI対話の回数と質（モデル）のみ
- 競合の失敗に学ぶ: Free版を機能制限で使い物にならなくする設計は離脱を生む

**課金モデル:** 全プラン月額固定制。従量制（API呼び出し単位課金）は採用しない。APIコストはプラン月額内で吸収し、AI対話回数の上限（Freeは20回/日、Basic/Pro/Premierはプラン別上限）で原価をコントロールする。Stripe Metered Billingはバックエンドのコスト計測に使用し、ユーザーへの請求は月額固定。

**Premierプランの対価（MVP時）:** チケット配布はショップ依存のため「Coming Soon」だが、PremierはPro同等の全機能に加えて①優先サポート（フィードバック対応を優先）②限定アバターフレーム1種（MVP同梱）③ショップ開始時のチケット遡及配布を保証。これにより課金時点で即座に差別化価値を提供する。

### 2.2 アイテム課金（ショップ）

アバターの装飾・フレーム・オーラ等をショップで個別購入。
Premierプランは月3枚のチケットで任意アイテムと交換可能。

**MVP（v0.1.0）:** ショップは未実装。Premierプランは選択・課金可能だがチケット配布は「Coming Soon」表示。

### 2.3 収益構造
1. **サブスクリプション** — Free→Basic→Pro→Premierのアップグレード
2. **アイテム課金** — アバター装飾の個別購入（v0.2.0以降）
3. **将来検討:** チームプラン、法人向け

### 2.4 プラン変更フロー

**アップグレード（Free→Basic→Pro→Premier）:**
- 即時反映。変更日から新プランのAIモデル/回数上限が適用
- 日割り計算: 旧プランの残日数分を新プランの初月から差し引き
- Stripe Subscriptionのproration機能で自動処理

**ダウングレード（Premier→Pro→Basic→Free）:**
- 月末まで現プランを維持。翌月1日から新プラン適用
- Premierの未使用チケットは月末で失効（遡及なし）
- ダウングレード予約中はME > PROFILE > 設定に「○月○日からBasicプランに変更予定」と表示。キャンセル可能

**支払い失敗:**
- Stripeのリトライ（3回、3日間隔）で再試行
- 3回失敗→Freeプランに自動ダウングレード→メール通知＋アプリ内バナー「お支払いの更新が必要です」
- データ/EXP/友達は保持。AIモデルと回数上限のみFree相当に制限

### 2.5 通知設計

| 通知種別 | タイミング | 内容 | 配信方法 |
|---------|----------|------|---------|
| タスクリマインダー | 開始時刻の15分前（設定変更可） | 「○○の時間です」 | Web Push |
| 日次サマリー | 午後9:00（設定変更可） | 「今日のEXP: +85。Lv.12まであと215」 | Web Push |
| 応援/メッセージ受信 | 即時 | 「YukiさんがあなたにGROWを送りました」 | Web Push + Realtime |
| 冒険EXP獲得 | AI対話中（リアルタイム） | アプリ内演出のみ（Push不要） | アプリ内 |
| レベルアップ | レベルアップ時 | アプリ内演出のみ（Push不要） | アプリ内 |
| 週次レポート | 月曜午前9:00 | 「先週のEXP: +520。新しい発見: 2件」 | Web Push |
| 支払い失敗 | Stripe失敗時 | 「お支払いの更新が必要です」 | メール + アプリ内バナー |

**通知設定:** ME > PROFILE > 設定 > 通知で種別ごとにON/OFF。デフォルト: タスクリマインダーON、日次サマリーON、応援受信ON、週次レポートON
**通知OFF時:** アプリ内バッジ（未読件数）は引き続き表示

## 3. 画面構成

### 3.1 ボトムタブ（3タブ）

| タブ | 名称 | 役割 |
|------|------|------|
| 1 | GROW | 今日のタスク＋ゴール管理＋育成進捗（メイン画面） |
| 2 | TALK | AIパートナーとの対話 |
| 3 | ME | 自分のすべて（プロフィール/自己理解/図鑑/ショップ） |

### 3.2 GROW画面（ヒーロー＋縦スクロール）

**ヒーロー領域（固定）:**
- アバター（SVGベース。レベルに応じて変化＋装飾反映）
- レベル表示（Lv.12 — Explorer）
- EXPプログレスバー（1,240 / 2,000 EXP）
- 小型端末対応: ヒーロー領域はスクロールに応じて縮小（アバター64x64→32x32、レベル/EXPバーは1行に圧縮）。キーボード表示時はヒーロー領域を完全非表示にし、スクロール領域を最大化

**スクロール領域:**
- **Today** セクション: 今日のタスク一覧（時間順）
  - タスク種別: 「単発タスク」と「習慣（繰り返し）」の2種類
  - 習慣は繰り返し周期を設定可能（毎日/平日/週N回/カスタム曜日）
  - Todayセクションには当日実行すべきタスク（単発+当日の習慣）を時間順で表示
  - 習慣の完了は当日分のみ記録（翌日にリセット）
  - タスクタップ→詳細パネル（編集/削除/AI相談）
  - 完了⭕️→EXP付与＋アニメーション
  - Undo: タスク完了から30秒以内に「取り消し」ボタンで完了を取り消し可能（EXPも取り消し）。30秒経過後は取り消し不可
  - タスク追加ボタン
  - タスク作成時の入力項目に「所要時間（見積り）」を追加。5分刻み（5/10/15/.../120分）のプリセット選択。デフォルト30分。タイムライン表示の幅計算に使用（EXP計算には使用しない）。
  - タスク作成時の入力項目に「開始時刻（任意）」を追加。設定時はTodayセクションで時刻順にソート。未設定のタスクは最後に表示。
- **Goals** セクション: ゴール一覧（進捗バー付き）
  - ゴールタップ→ゴール詳細画面（タスク分解/AI相談/進捗）
  - ゴール-タスク紐付け: ゴール作成時に「このゴールに紐づくタスク」を追加可能。進捗バー = 紐づくタスクの完了数 ÷ 全タスク数 × 100%。ゴール完了条件 = 紐づく全タスクが完了。手動で「ゴール完了」マークも可能（タスクなしゴール用）。習慣（繰り返し）タスクはゴールに紐付け不可。ゴールに紐づけるのは単発タスクのみ（達成可能な有限のステップとして設計）
  - ゴール詳細で分解されたタスクは実行予定日を設定可能。予定日が当日のタスクがTodayセクションに自動表示。予定日未設定のタスクはゴール詳細画面でのみ表示
  - 新規ゴール作成

**3.2.1 タスク追加フロー（GROW画面から）:**
1. 「+」ボタンタップ
2. タスク種別選択: [単発タスク] / [習慣（繰り返し）]
3. タスク名入力（必須。1-100文字）
4. 開始時刻（任意。タップで時刻ピッカー表示）
5. 所要時間（任意。5分刻みプリセット。デフォルト30分）
6. [単発の場合] 実行予定日（デフォルト=今日。カレンダーピッカー）
   [習慣の場合] 繰り返し周期選択: 毎日 / 平日 / 週N回 / カスタム曜日
7. ゴール紐付け（任意。既存ゴールリストから選択。単発タスクのみ）
8. メモ（任意。自由テキスト。500文字以内）
9. [作成] → Todayセクションに即時反映（当日タスクの場合）

**3.2.2 ゴール作成フロー:**
1. Goals セクションの「+新しいゴール」タップ
2. ゴール名入力（必須。1-100文字）
3. 期限（任意。カレンダーピッカー。設定なし=無期限）
4. カテゴリ選択（仕事/健康/学習/趣味/人間関係/その他。複数選択可）
5. タスク分解（任意。「タスクを追加」で紐づくタスクを作成。0件でも作成可能）
6. [作成] → Goals セクションに即時反映

**3.2.3 週N回習慣のToday表示ロジック:**
- 「週3回」の場合: 月曜から日曜の7日間で3回完了が目標
- Today表示判定: (今週の残り日数) ≥ (今週の残り必要回数) の場合にTodayに表示。つまり「今日やらなくても週内に達成可能」なら表示しない。「今日以降毎日やらないと達成不能」になった時点で表示
- 例: 週3回、木曜時点で0回完了 → 残り3日で3回必要 → 木金土日に毎日表示
- ユーザーが手動でTodayに追加することも可能（「今日やる」ボタン）
- 週の区切り: 月曜始まり（午前4:00 JSTにリセット）

**3.2.4 Overdueタスクの扱い:**
- 予定日が過去の未完了単発タスクは「Overdue」ラベル付きでTodayセクションの最上部に表示
- 色: 通常タスクと異なるアクセントカラー（テーマ定義に依存。design_system.mdで確定）
- 操作: 通常タスクと同じ（完了/編集/削除/AI相談）
- 「明日に延期」ボタン: タップで予定日を翌日に変更。Todayから消える
- 習慣タスクは「Overdue」にならない（毎日リセットされるため）

**3.2.5 日次リセット（午前4:00 JST）:**
対象:
- AI対話回数カウンター → 0にリセット
- EXP日次上限カウンター → 0にリセット
- 習慣タスクの完了状態 → 未完了にリセット
- ログインボーナス付与可能フラグ → リセット
- Todayセクションの表示タスク → 当日分に更新
タイムゾーン: サーバーサイドで一律JST基準。ユーザーのローカルタイムゾーンには依存しない（海外ユーザー対応はv0.2.0以降で検討）

**3.2.6 タスク完了→EXP→演出フロー:**
1. ユーザーがタスクの⭕️をタップ
2. タスクに完了チェックマークが付く（即時UI更新）
3. Undoスナックバーが画面下部に5秒間表示（「取り消す」ボタン付き。タップで完了取消＋EXP返却）。スナックバー消去後も30秒以内ならタスク行の⭕再タップで取り消し可能
4. サーバーにタスク完了＋EXP付与リクエスト送信
5. サーバーが1日上限を検証→OK→EXP付与確定
6. クライアントにEXP付与通知→ヒーロー領域のEXPバーがアニメーション伸長（0.5秒）→「+10 EXP」フロートテキストが上に飛ぶ（0.8秒でフェードアウト）
7. レベルアップ条件を満たした場合: EXPバー到達→バー全体が光る（0.3秒）→レベル数字がカウントアップ→称号テキストが変更→アバターに変化がある場合はアバター進化アニメーション（1.5秒。旧PNGがglow+fade out→新PNGがscale(1.2→1)で出現。SVGモーフィングではなくラスタライズ済みPNG切替。§7.3のCanvas/PNG方式と整合）
8. ゴール完了条件を満たした場合: ゴール進捗バーが100%に到達→ゴール完了演出（紙吹雪エフェクト2秒＋「🎉 ゴール達成！+50 EXP」バナー表示3秒）

**3.2.7 空状態定義:**
- **タスク0件:** 「今日のタスクはまだありません」＋「+タスクを追加」ボタン＋「AIに相談して計画を立てる」リンク（TALK画面に遷移）
- **ゴール0件:** 「目標を設定して冒険を始めましょう」＋「+ゴールを作成」ボタン＋ゴール例3件（「運動習慣をつける」「スキルアップ」「読書10冊」）をタップで即作成

### 3.3 TALK画面

AIパートナーとの対話空間。
- チャット送受信（ストリーミング表示）
- マルチAIルーティング（GPT/Claude/Gemini。ユーザーには透過的）
- 冒険EXP自動検出（対話内容からAIが判定→EXP付与＋演出）
- 画像添付（対応フォーマット: JPEG/PNG/GIF/WebP。サイズ上限: 10MB。サーバーでリサイズ（長辺1200px）＋EXIF情報削除後にSupabase Storageに保存。保存期間: AI対話履歴と同じ90日。Vision API対応モデル（GPT-5/Gemini）に自動ルーティング。Free版はGPT-4o miniのVision機能で処理）
- 過去会話履歴（履歴読み込み: 直近50件を初期表示。上スクロールで追加読み込み（50件ずつ、無限スクロール方式））
- キーボード対応: visualViewport APIでビューポート変化を監視し、キーボード表示時に入力フィールドとメッセージリストの高さを動的調整。iOS PWAのviewport bug対策としてposition:fixedの入力バーは使用せず、flexboxレイアウトで対応
- **空状態（会話0件）:** 「AIパートナーに何でも話してみましょう」＋会話のきっかけチップ3個（「今日の予定を相談」「目標について話す」「気分を話す」）。チップタップで定型文が入力欄にセットされる

**3.3.1 会話→タスク化フロー**

AIが対話内容からユーザーの「やるべきこと」を検出し、タスク登録を提案する。

**単一タスク検出:**
```
ユーザー: 「来週までに企画書を出さないと」
AI: 通常の応答（アドバイス等）
    ＋ タスク提案カード表示:
    ┌──────────────────────────┐
    │ 📋 タスクにしますか？      │
    │ タスク名: 企画書を提出する  │
    │ 期限: 4/18（金）           │
    │ [登録する] [編集して登録] [不要] │
    └──────────────────────────┘
```
- 「登録する」→ タスク名/期限をそのままGROWに登録。トースト「タスクを登録しました」
- 「編集して登録」→ タスク名/期限/開始時刻/所要時間/ゴール紐付けを編集するパネルを表示→登録
- 「不要」→ カードを非表示。以降同じ文脈では再提案しない

**複数タスク検出:**
```
ユーザー: 「明日は朝ジムに行って、午後に歯医者、夜は友達と飲み会」
AI: 通常の応答
    ＋ 複数タスク提案カード:
    ┌──────────────────────────┐
    │ 📋 3つのタスクが見つかりました │
    │ ☑ ジムに行く（明日 朝）     │
    │ ☑ 歯医者（明日 午後）      │
    │ ☑ 友達と飲み会（明日 夜）   │
    │ [まとめて登録] [個別に編集] [不要] │
    └──────────────────────────┘
```
- 各タスクのチェックで選択/解除可能
- 「まとめて登録」→ チェック済みタスクを一括登録
- 「個別に編集」→ 各タスクの編集パネルを順に表示

**タスク検出ロジック:**
- AI応答生成時に並行してタスク抽出分類を実行（冒険EXP検出と同じレイヤー）
- 抽出対象: 「〜しなきゃ」「〜する予定」「〜までに」「〜に行く」等の行動意図を含む発言
- 抽出結果のJSON形式: `{"tasks": [{"name": "企画書を提出する", "due_date": "2026-04-18", "start_time": null, "confidence": 0.85}]}`
- confidence 0.7未満のタスクは提案しない
- 1メッセージあたり最大5タスクまで提案
- ユーザーが「不要」を選択したタスクパターンは学習し、類似パターンの提案頻度を下げる

**ゴール紐付け提案:**
- 「編集して登録」時に既存ゴールリストを表示し、AIが最適なゴールを推薦（推薦スコア付き）
- 該当ゴールなしの場合は「紐付けなし」がデフォルト
- 新規ゴール作成も可能（ゴール名入力→即作成→紐付け）

### 3.4 ME画面（ヒーロー＋4サブタブ）

**ヒーロー領域（固定）:**
- アバター（装飾込み）
- 名前＋レベル
- EXPプログレスバー

**サブタブ:**

**PROFILE:**
- 基本情報入力（年齢/職業/趣味。全て任意。未入力項目はプレースホルダー「タップして入力」表示。名前はヒーロー領域に表示済みのため基本情報リストには含めない。セクションラベル「基本情報」も不要）

## 4. EXP（経験値）設計

### 4.1 コンセプト
EXPは「本当の人生経験」の可視化。タスク消化ゲームではなく、日常を認めつつ挑戦を讃える。

### 4.2 3層モデル

| 層 | 行動例 | EXP目安 | 判定方法 |
|----|--------|--------|---------|
| 呼吸 | アプリ起動、ログインストリーク | ログインボーナス=5 EXP/日（固定） | システム自動 |
| 日常 | ルーチンタスク完了、仕事に行く | タスク完了=10 EXP（固定。タスク種別・所要時間によらず一律） | タスク完了イベント |
| 冒険 | 新しいゴール設定、初めての挑戦、新しい出会い | 50 EXP（固定。1日2回まで） | AI対話から自動検出 |

**ゴール達成ボーナス:** ゴール完了時に50 EXP（固定。1日1回まで。タスク数によらない）。ゴール作成から完了まで最低7日間経過が必要（即時完了防止）。タスクなしゴールの手動完了も同額。7日未満で紐づく全タスクを完了した場合: ゴールは「完了待ち」状態になり、作成から7日経過後に自動でゴール完了＋ボーナスEXP付与。進捗バーは100%表示のまま「あとN日で完了！」と表示

### 4.3 冒険EXP — AI自動検出

AIが対話内容を分析し、以下の文脈を検出した場合に冒険EXPを付与:
- 「初めて○○した」「新しい○○に挑戦した」
- 「○○に出会った」「知らない人と話した」
- 「怖かったけどやってみた」「いつもと違うことをした」

**実装方式:** AIの応答生成時に分類レイヤーを挟む。ルーティング層で処理し、EXP付与＋冒険演出をトリガー。

### 4.4 レベルシステム

**レベルキャップ:** 50（v0.1.0）。将来拡張可能。
**レベルアップ計算式:** 次レベルに必要なEXP = `100 + (現在レベル - 1) × 50`
**累計EXP計算式:** レベルNに到達するために必要な累計EXP = `(N-1) × (50 + 25N)`

| Lv | 次Lvに必要EXP | 累計EXP | 到達目安 | 称号 | アバター変化 |
|----|-------------|---------|---------|------|------------|
| 1→2 | 100 | 0 | 1日目 | Beginner（Lv.1-4） | 初期アバター |
| 5→6 | 300 | 700 | 1週間 | Seeker（Lv.5-9） | 表情変化 |
| 10→11 | 550 | 2,700 | 1ヶ月 | Explorer（Lv.10-14） | 服装変化 |
| 15→16 | 800 | 5,950 | 2ヶ月 | Challenger（Lv.15-19） | 背景エフェクト追加 |
| 20→21 | 1,050 | 10,450 | 3ヶ月 | Adventurer（Lv.20-29） | 全身リデザイン |
| 30→31 | 1,550 | 23,200 | 7ヶ月 | Pathfinder（Lv.30-39） | オーラ追加 |
| 40→41 | 2,050 | 40,950 | 1年 | Visionary（Lv.40-49） | 特別エフェクト |
| 50 | — | 63,700 | 1.7年 | Master（Lv.50） | Master専用ビジュアル |

**設計意図:**
- 初日にLv.2到達可能（ログイン5 + タスク5個50 + 冒険50 = 105EXP。100EXPで到達）→ 初回体験でレベルアップの快感を提供
- 1週間でLv.5→称号変更→継続モチベーション
- 長期プレイヤーの目標としてLv.50 Master（約1.7年）

**Lv.50到達後:** EXPは引き続き蓄積される（表示は累計EXP）。レベル/称号はMaster固定。将来のレベルキャップ拡張で自動的に新レベルに昇格

- レベルに応じてアバターが自動変化（基本ビジュアルの進化）
- アバター進化: 5段階（Lv1-5: Phase 1 / Lv6-15: Phase 2 / Lv16-30: Phase 3 / Lv31-45: Phase 4 / Lv46-50: Phase 5）。各Phaseで基本シルエット・配色が変化。MVPではPhase 1-3の3段階分のアセットを用意（各3バリエーション = 9アセット）
- 装飾購入はレベルとは別（ショップ経由）

### 4.5 EXP上限・不正対策

| 制約 | 値 | 理由 |
|------|------|------|
| 1日の獲得EXP上限 | 300 EXP（呼吸EXP + 日常EXP + 冒険EXPの合計が対象。ゴール達成ボーナス50EXPは別枠）。理論上の1日最大EXP = 300 + 50 = 350 EXP | インフレ防止。初日にLv.2到達可能（100EXP）だが、Lv.10到達には約8日必要 |
| 冒険EXP 1日上限 | 100 EXP（最大2回判定） | AI判定の誤検出を制限。1日に2つ以上の「冒険」は稀 |
| タスクEXP連続取得制限 | 同名タスク5分以内の再完了は無効 | ダミータスク大量完了の防止 |
| 呼吸EXP | 1日1回のみ | ログイン連打防止 |

**リセットタイミング:** AI対話回数・EXP日次上限ともに毎日午前4:00（JST）にリセット。ゴール達成ボーナスも日次リセットの影響を受ける。

**Pay-to-Win対策:** 冒険EXPは対話回数ではなく「内容」で判定し、1日2回上限を全プラン共通とする。Free(20回/日)でも冒険EXPの最大獲得量はPremierと同一。課金で増えるのはAIの質（深い対話体験）であり、EXP獲得速度ではない。

**不正検出:** 同一文脈の繰り返し投稿（「初めて○○した」の連投）はAI分類層で検出し、2回目以降は冒険EXPを付与しない。検出ロジックはサーバーサイドで実行し、クライアント操作では回避不能。

### 4.6 競合との差別化
- Habitica: タスク完了＝ゲーム報酬。未完了＝HP損失（罰）。Laisは罰なし
- Finch: ペットの成長。Laisは「自分自身」の成長を可視化
- 一般的な習慣トラッカー: ストリーク重視→途切れると挫折。Laisはストリーク途切れてもEXPは減らない

## 5. ソーシャル機能

### 5.1 友達登録（QR交換）
- ME > FRIENDS画面でQRコード表示
- 相手のQRをスキャン→相手の公開プロフィール（アバター+名前+レベル）を確認→「友達リクエストを送る」ボタン→相手が承認→双方の図鑑に登録
- Supabaseにフレンド関係を保存
- リモート友達追加: QR対面交換に加え、シェアリンク（URLをメッセージアプリ等で送信）のみ。表示名検索はスパム/プライバシーリスクのため非搭載

### 5.2 図鑑
- 出会った人がカード形式で並ぶ
- 各カード: アバター（装飾込み）+ レベル + 称号
- EXPの数値は非公開（レベルとビジュアルでのみ推測可能）
- タップで詳細表示

### 5.3 簡易メッセージ/応援
- **友達リクエスト:** ME > FRIENDS画面の上部に「リクエスト」タブ（受信リクエスト一覧。承認/拒否ボタン付き）を追加。送信済みリクエストのステータスも表示
- ワンタップ応援（定型メッセージ＋通知）
- テキストメッセージ送信（短文100文字以内。チャットアプリにはしない）
- **受信場所:** ME > FRIENDS画面の上部に「お知らせ」バッジ表示。タップで受信一覧（応援/メッセージ）を時系列で表示。未読件数をタブアイコンにバッジ表示
- **通知配信:** Web Push API（Service Worker経由）でアプリ非起動時も配信。Supabase RealtimeはApp起動中のリアルタイム更新に使用。Web Push未対応環境ではアプリ起動時にポーリングで取得
- **iOS制約:** Web PushはPWA（ホーム画面追加）時のみ有効。Safari単体では通知不可。初回起動時にカスタムインストール誘導UIを表示する（iOSはbeforeinstallprompt APIが未対応のため、「共有ボタン→ホーム画面に追加」の手順を画像付きで案内するモーダル。Androidはネイティブインストールプロンプトを使用）。PWA未インストール時はアプリ起動時のポーリングにフォールバック

### 5.4 プライバシー設計
- 公開情報: アバター、レベル、称号、表示名（display_name）
- 非公開: EXP数値、タスク内容、ゴール内容、AI対話内容、プロフィール詳細
- ブロック/解除機能
- 友達リストは本人のみ閲覧可能
- QRコードに含まれる情報: ユーザーUUID + 一時トークン（24時間有効、サーバー発行）を含む。トークンはQRコード表示時にAPIから取得し、スキャン後のプロフィール一時閲覧に使用。期限切れ後は再表示でトークン更新。名前・レベル等の個人情報はQRコード自体には含まない。スキャン後にサーバー側でトークンを検証しユーザー情報を取得
- 友達登録は**相互承認制**: QRスキャン→リクエスト送信→相手が承認→双方の図鑑に登録。片側登録は不可

### 5.5 悪用防止
- メッセージ: 定型＋短文100文字制限でスパム/ハラスメントを構造的に抑制
- 通報機能: 各メッセージに「通報」ボタン。通報されたメッセージは管理者レビュー待ちキューに入る
- ブロック時: 相手の図鑑から自分が非表示になる。メッセージ/応援の送受信を双方向で遮断

## 6. AI設計

### 6.1 マルチAIルーティング
ユーザーには透過的に最適なAIモデルを選択。**ルーティングはBasic以上のプランで有効。**

| カテゴリ | 割当モデル | 判定基準 |
|---------|----------|---------|
| 感情コーチング（核心） | Claude | 共感・深い対話が必要な場面 |
| 検索・事実・比較 | Gemini | 情報検索、比較、客観的回答 |
| 汎用対話 | GPT | catch-all。日常会話、タスク相談 |
| 短い返答 | GPT-simple | 挨拶、確認、単純な質問 |

**プラン別AI挙動:**
- **Free:** GPT-4o mini固定（ルーティングなし）。全カテゴリをGPT-4o miniで処理
- **Basic:** GPT-5 + Gemini Flash。感情コーチングもGPT-5で処理（Claudeなし）
- **Pro:** フルルーティング有効。Claude Sonnet + GPT-5 + Gemini Pro
- **Premier:** Pro同等だがClaude Opus（最高品質の感情コーチング）

**AI対話1回のカウント:** ユーザーが1メッセージ送信→AIが1応答を返す = 1回。ストリーミング中のチャンク分割は1回としてカウント。システムメッセージ（EXP通知等）はカウント対象外

**上限到達時のUI:** 入力フィールドを無効化し、「本日の対話回数に達しました。リセット: 明日 04:00」と表示。Freeユーザーには「Basicにアップグレードで100回/日に」のCTA表示

### 6.2 冒険EXP検出
AI応答生成時に並行して分類を実行:
1. ユーザー発言を冒険/日常/その他に分類
2. 冒険判定→EXPトランザクション発行→クライアントに演出指示
3. 分類結果はログとして保存（将来の精度改善用）

### 6.3 AI理解メモ
対話履歴からユーザーの性格・価値観・強み・弱みを要約。
5回の対話ごとに自動更新。ME > PROFILE画面に表示。

### 6.4 AIデータプライバシー
- **外部API送信データ:** AI対話時にユーザーの発言をOpenAI/Anthropic/Google APIに送信する。送信前にPII（メールアドレス、電話番号、URL）を正規表現で自動マスキング。日本語氏名・住所等の文脈依存PIIは完全な自動検出が困難なため、プライバシーポリシーで「AI対話に個人情報を含めないことを推奨」と案内し、ユーザー教育で対応。将来的にはNERモデルによる高精度マスキングを検討
- **AIモデルの学習:** OpenAI API（opt-out済み）、Anthropic API、Google Gemini APIはいずれもAPI経由のデータをモデル学習に使用しない設定で利用。各社のData Processing Agreementに基づく
- **データ保存:** AI対話履歴はSupabaseに保存。保存期間は直近90日（それ以前は自動削除）。ユーザーは設定画面から「対話履歴を削除」を実行可能
- **プライバシーポリシー:** アプリ内およびWebサイトにプライバシーポリシーを掲載。AI対話データの取り扱いを明記

### 6.5 退会・データ削除
- ME > PROFILE > 設定 >「アカウント削除」から退会可能
- **退会フロー:** ①ユーザーが「アカウント削除」を実行→account_statusを「deleted_pending」に変更→即時ログアウト ②有料プランの場合: Stripeサブスクに`cancel_at_period_end: true`を設定（現在の請求期間終了時に自動解約。即座にはサービス停止しない） ③72時間のクーリングオフ期間（期間中にログインで削除キャンセル可能） ④72時間経過後にWorker CronジョブがSupabaseの全データを物理削除＋Stripeサブスクを即時キャンセル（`cancel_at_period_end`ではなく即座に解約） ⑤Freeプランユーザーも同一フロー（Stripeステップをスキップ）。クーリングオフ中にログインで削除キャンセルした場合: account_statusを通常に戻す＋Stripeの`cancel_at_period_end`を解除してサブスク継続。返金なし
- 退会時の削除対象: Supabase上の全ユーザーデータ（プロフィール、タスク、ゴール、AI対話履歴、EXP、友達関係）＋友達の図鑑から自分のカードを削除
- 削除は不可逆。確認ダイアログで「アカウントを削除」を2回入力して実行
- App Store / Google Play審査ガイドライン準拠: アカウント削除機能をアプリ内に提供
- **注意: サブスク解約（プラン変更/ダウングレード）とアカウント削除は完全に別のフロー。サブスク解約ではデータは一切削除しない**

### 6.6 AIっぽさの排除
- 定型的な「〜ですね！」「素晴らしいですね！」を避ける
- ユーザーの文脈に応じた自然な応答
- dev-system §4.7準拠

| ホスティング | Cloudflare Pages |
| データベース | Supabase (PostgreSQL + pgvector) |
| リアルタイム更新 | Supabase Realtime（App起動中） |
| プッシュ通知 | Web Push API + Service Worker（App非起動時） |
| 決済 | Stripe Subscription（月額固定）+ Metered Billing（内部コスト計測） ※ LaisはPWA（Webアプリ）であり、App Store/Google Playを経由しない。Stripe直接決済が可能。将来のネイティブラッパー（TWA/WebView）化時にはIAP対応を別途検討 |
| AI | GPT-5 / Claude Sonnet・Opus / Gemini Pro・Flash |
| 認証 | Supabase Auth（メール/パスワード + Magic Link） |

### 7.2 認証設計
- **認証方式:** Supabase Authを使用。メール/パスワード認証 + Magic Link（パスワードレス）
- **ソーシャルログイン（v0.2.0以降）:** Google / Apple Sign-In。MVPではメール認証のみ
- **セッション管理:** JWT（Supabase発行）。アクセストークン有効期限1時間、リフレッシュトークン30日
- **RLS:** 基本は自分のデータのみCRUD可能。ソーシャル機能用の例外: ①friends テーブルは相互のuser_idで双方が参照可能 ②profiles テーブルの公開フィールド（avatar, level, title, display_name）はSELECT: 友達関係にあるユーザー＋友達リクエスト中のユーザー（pending状態）＋QRスキャン後の一時確認（リクエスト送信前の24時間限定トークン）が可能 ③social_messages テーブル: INSERT=送信者がauthユーザーかつ受信者が友達関係にあるユーザーのみ。SELECT=送信者・受信者の双方 ⑤ai_messages テーブル: 自分のデータのみCRUD可能（他ユーザーのAI対話は一切参照不可） ④シェアリンク経由のアクセス: リンクに含まれる一時トークン（24時間有効）でprofilesの公開フィールドがSELECT可能
- **パスワードポリシー:** 最低8文字、英数字含む

### 7.3 新規追加
| 機能 | 技術 |
|------|------|
| QRコード生成 | qrcodeライブラリ（クライアントサイド） |
| QRスキャン | カメラAPI + jsQRライブラリ |
| アバターシステム | SVGレイヤー合成（パーツ: 顔/髪/装飾/フレーム/オーラ）。リスト表示時はCanvas経由でラスタライズ済みPNG（64x64）をキャッシュ表示。SVG直接レンダリングはプロフィール詳細画面のみ。**SVG座標系:** viewBox: 0 0 200 200（全パーツ200x200キャンバスで設計）。レイヤー順（下から上）: background → body → hair → face → accessory → frame → aura。アンカーポイント: center (100, 100)。各パーツは一貫したviewBoxを持つSVG `<g>` 要素 |
| グローバルステート | Preact Signals |
| PWA | Service Worker（オフラインタスク表示＋オンライン同期）。**オフラインタスク完了:** ローカルに完了を記録し、オンライン復帰時にサーバーと同期。同期時はサーバー側でEXP制限（1日上限300EXP）を再検証し、上限超過分は付与しない（冪等性保証）。同期APIはリクエストIDによる重複排除を実装。**TALK画面:** オフライン時は入力フィールドを無効化し、「オフラインです。接続を復旧してください」のバナーを表示。送信済みだが応答未受信のメッセージは「送信中...」表示のまま保持し、オンライン復帰時に再送信。**オフラインEXP方針:** クライアント側ではEXP付与を表示しない（「同期待ち」バッジ表示）。オンライン復帰後にサーバーがEXP計算→結果を反映。巻き戻しは発生しない設計（サーバー権威モデル） |

### 7.3 アーキテクチャ原則
- 1コンポーネント300行以内（超過なら分割）
- コンポーネントは自前のstateを持ち、window.*グローバルに依存しない
- API呼び出しはimportで使う（window.apiXxx廃止）
- イベントリスナーはuseEffect内で管理（unmountで自動解除）

### 7.4 データライフサイクル

| データ種別 | 生成 | 保存先 | 更新 | 削除/保持 |
|----------|------|-------|------|----------|
| タスク（単発） | ユーザー作成 or AI提案 | Supabase tasks | 編集/完了/Undo | 完了後90日で自動アーカイブ。アーカイブ=表示対象外だがDB保持。退会時に物理削除 |
| タスク（習慣） | ユーザー作成 | Supabase habits | 周期設定変更 | ユーザー削除のみ。完了履歴は90日保持 |
| ゴール | ユーザー作成 | Supabase goals | 進捗更新/完了 | 達成後も永続保持（成長記録として）。退会時に物理削除 |
| AI対話 | ユーザー送信 | Supabase ai_messages | — | 90日で自動削除。手動削除可 |
| EXP | タスク完了/冒険検出/ログイン | Supabase user_exp | 加算のみ（減算なし） | 永続保持。退会時に物理削除 |
| 友達関係 | QR交換+承認 | Supabase friends | — | 友達解除 or ブロックで論理削除。退会時に物理削除 |
| メッセージ | ユーザー送信 | Supabase social_messages | — | 90日で自動削除。友達解除時に双方から即時削除 |
| アバター装飾 | 購入 or チケット交換 | Supabase user_items | — | 永続保持（購入済みアイテムは失効しない）。退会時に物理削除 |
| 画像添付 | ユーザーアップロード | Supabase Storage | — | 対話と同じ90日。自動削除 |

**バックアップ:** Supabaseの日次自動バックアップ（Supabase Pro以上で利用可能）。ユーザー向けエクスポートはv0.2.0以降で検討
**データ量上限:** タスク1ユーザーあたり最大10,000件（アーカイブ含む）。ゴール最大100件。友達最大500人

## 9. ユーザーの声に基づく設計判断

類似アプリの実際のユーザーレビュー（Habitica/Finch/Habitify/Streaks/HabitKit/Loop等、2025-2026年）から抽出した知見と、Laisの設計判断の対応。

### 9.1 離脱要因と対策

| 離脱要因（実際のユーザーの声） | Laisの対策 |
|----------------------------|----------|
| 「Free版が3習慣しか作れない。無料を騙っている」（Habitify） | Free版でもタスク/ゴール/EXP/ソーシャル全機能開放。制限はAIモデルと回数のみ |
| 「タスク未完了でHP損失→パーティに被害→ストレスで辞めた」（Habitica） | 罰なし設計。EXPは増えるだけで減らない。ストリーク途切れもペナルティなし |
| 「ゲーミフィケーションに最初は興奮したが数週間で飽きた」（Habitica） | 「構造」を借りて「見た目」は洗練。飽きるのはUI演出であり、育成と発見のループの深さが継続を生む |
| 「15個の習慣を設定→全部やれなくて罪悪感→アプリを開かなくなった」（Reddit複数） | 「呼吸」層: アプリを開くだけでEXP。完璧を求めない設計 |
| 「アプリが30-45秒フリーズする。毎日使うアプリでこの摩擦は致命的」（Habitify） | Cloudflare Pagesで高速配信。PWAオフライン表示。パフォーマンスをdev-system品質ゲートに含む |
| 「一度買い切りだったのにサブスク移行→ライフタイム購入者がアクセス喪失」（Done/Do Habits） | 最初からサブスクモデル。プラン変更時は既存ユーザーの権利を保護 |

### 9.2 継続要因の取り込み

| 継続要因（実際のユーザーの声） | Laisでの実現 |
|----------------------------|------------|
| 「GitHub風の貢献グラフで進捗が可視化→ゲーム感覚で維持」（HabitKit） | EXP/レベルの成長可視化＋ゴール進捗バー |
| 「ペットが自分のために待ってくれている感覚→毎日開く」（Finch） | アバターが自分自身→自己投影で開く動機 |
| 「シンプルで直感的なUIが最も重要」（複数アプリで共通） | 3タブ構成。最小限のタップで主要操作完了 |
| 「開発者がレビューに応答＋要望を実装してくれた」（HabitKit/AwesomeHabits） | ソロ開発者として直接フィードバック対応。SNS(X)で開発ログ公開 |
| 「気分と習慣の相関が見える→自分を理解できる」（Daylio） | AI理解メモ＋DISCOVER画面で自己理解を蓄積 |
| 「罰がないから安心して使える。鳥がただ待っていてくれる」（Finch） | 罰なし＋EXP減少なし＋呼吸EXPで「開くだけで前進」 |

## 11. AIレビュー計画

本仕様書はdev-system同様のAIレビュープロセスを経て確定する。

### 11.1 レビューペルソナ（8種）

**ペルソナ1: プロダクトマネージャー**
コンセプトの一貫性、ターゲットとのフィット、MVP範囲の妥当性、収益モデルの持続可能性。

**ペルソナ2: UXデザイナー**
画面構成の直感性、操作フロー、情報設計、3タブの妥当性、サブタブの使いやすさ。

**ペルソナ3: ゲームデザイナー**
EXPシステムのバランス、レベルカーブ、冒険検出の設計、飽きない仕組み、ソーシャル動機。

**ペルソナ4: セキュリティ/プライバシー専門家**
ソーシャル機能のプライバシー設計、QR交換の安全性、データ公開範囲、GDPR考慮。

**ペルソナ5: ターゲットユーザー（実ユーザー視点）**
類似アプリ（Habitica/Finch/Habitify等）の実際のユーザーレビューに基づく視点。
「自分が使いたいか」「続けられるか」「課金したいか」「友達に勧めるか」を判断。

**ペルソナ6: 一般ユーザー（非テック、非自己啓発層）**
友人に勧められて初めて試す立場。初見で理解できるか、面倒くさくないか、オンボーディングの有無。

**ペルソナ7: Webデザイナー**
ビジュアルデザインの方向性、ブランド一貫性、SVGアバター実現性、テーマ/カラー/タイポグラフィ。

**ペルソナ8: アプリUXデザイナー**
iOS/Android HIG/Material Design準拠、ジェスチャー設計、アクセシビリティ、ローディング/エラー状態。

### 11.2 レビュー方式
- 8ペルソナ × 2モデル（Gemini 3 Pro Preview + GPT-5）= 16回
- 出力: JSON [{severity, category, location, issue, suggestion}]
- 最低10ラウンド。CRITICAL 0になるまで修正→再レビュー
- dev-system §13.9（severity inflation対策）適用
- 全ペルソナ共通で「実装十分性」を必ず検証: この仕様書だけを読んだAIエンジニアがPOの想定通りに実装できるか。暗黙の前提や省略された仕様がないか

### 11.3 レビュー後のファイル作成順序
1. project_v1.md確定（本ファイル）
2. ux_v1.md作成→レビュー→確定
3. design_system.md作成→レビュー→確定
4. 以降、§10.1のロードマップに従う
